# CLAUDE.md — правила проекта «Суть»

Полный план и все решения описаны в `plan.md`. Прочитай его перед началом работы и двигайся по фазам из раздела 14, отмечая чек-листы.

## Контекст
- Нативное iOS-приложение (Swift 6, SwiftUI, SwiftData, iOS 17+) и бэкенд на Go (PostgreSQL + pgvector, River).
- Разработка на Mac M4. Установка на iPhone через Xcode (Personal Team, без App Store).
- Макеты экранов лежат в `design/*.dc.html`; ссылка на живой макет — в начале `plan.md`. Цвета, шрифты и размеры бери из раздела 12 `plan.md`, а не придумывай.

## Жёсткие правила
- **iOS: ноль сторонних зависимостей.** Только системные фреймворки (SwiftUI, SwiftData, CryptoKit, BackgroundTasks, UserNotifications).
- **Профиль и фильтры пользователя никогда не отправляются на сервер.** Сервер отдаёт одинаковые данные всем, подбор делает FilterEngine на устройстве.
- Бэкенд: минимум зависимостей; каждую новую зависимость обосновать в PR/коммите.
- Секреты только через переменные окружения, никогда в коде и репозитории.
- LLM на бэкенде извлекает и классифицирует строго в JSON по схеме; невалидный ответ повторяется, но не «чинится» догадками.
- Законы попадают в API только с `verified = true`.
- Источники из реестров нежелательных организаций и иноагентов не добавляются в каталог.

## Как работать
- Одна фаза — одна ветка. Небольшие коммиты с понятными сообщениями на русском или английском.
- Перед переходом к следующей фазе: сборка проходит, тесты зелёные, результат фазы проверяется вручную (для iOS — запуск на симуляторе и iPhone).
- FilterEngine, AudienceMatcher и склейка сюжетов покрываются unit-тестами.
- Swift: strict concurrency, `@Observable`, без force unwrap в продуктовом коде.
- Go: `go vet`, `gofmt`, `govulncheck`, контексты с таймаутами на все внешние вызовы.
- Если решение в `plan.md` мешает, спроси прежде чем менять его, и обнови `plan.md` после согласования.

```bash
cd backend && go run ./cmd/api

# iOS

```
